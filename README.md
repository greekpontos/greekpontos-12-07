### Задание 1
**Опишите основные преимущества использования масштабирования методами:**
1. Активный master-сервер и пассивный репликационный slave-сервер;
2. Master-сервер и несколько slave-серверов.

#### Решение:
* **Активный master и пассивный slave (Active-Passive / Failover):**
  * **Высокая отказоустойчивость (High Availability):** Если основной (master) сервер выходит из строя, пассивный сервер (slave) готов мгновенно переключиться и принять на себя всю нагрузку, минимизируя время простоя системы (Downtime).
  * **Надежность хранения данных:** Пассивный сервер выступает в роли точной резервной копии в реальном времени. В случае аварии на master-сервере данные остаются в сохранности.
  * **Снижение нагрузки при бэкапах:** Процедуру снятия резервных копий (бэкапов) можно полностью перенести на пассивный slave-сервер, чтобы не снижать производительность активного master-сервера.

* **Master и несколько slave-серверов (Read-Scaling):**
  * **Масштабирование операций чтения (Load Balancing):** Все операции изменения данных (INSERT, UPDATE, DELETE) берет на себя master, а тяжелые и многочисленные запросы на чтение (SELECT) распределяются между несколькими slave-серверами. Это кратно повышает общую пропускную способность системы.
  * **Географическое распределение:** Slave-серверы можно развернуть в разных дата-центрах поближе к конечным пользователям, снижая задержку (latency) при получении информации.
  * **Устойчивость к пиковым нагрузкам:** При росте посещаемости можно динамически добавлять новые slave-серверы для распределения входящего трафика. В случае падения одного из slave-узлов система продолжит стабильно работать за счет остальных.

### Задание 2
**Разработайте план для выполнения горизонтального и вертикального шардинга базы данных.**
* База данных состоит из трёх таблиц: `пользователи`, `книги`, `магазины`.
* Опишите принципы построения системы, разграничение/разбивку данных и режимы работы серверов.

#### Решение:

##### 1. Вертикальный шардинг (Vertical Sharding)
Разделение системы на уровне бизнес-сущностей. Каждая таблица переносится на отдельный физический сервер (инстанс БД) для изоляции нагрузки:
* **Сервер А (БД Пользователи):** хранит таблицу `users` (id, user_name, email, password_hash, registration_date).
* **Сервер Б (БД Каталог Книг):** хранит таблицу `books` (id, title, author_name, genre, price, isbn).
* **Сервер В (БД Магазины):** хранит таблицу `stores` (id, branch_name, address, phone_number).

##### 2. Горизонтальный шардинг (Horizontal Sharding)
Разбивка строк внутри одной таблицы по определенному признаку (**Shard Key**) для распределения объемов данных. Применим его к наиболее быстрорастущим таблицам `users` и `books`:
* **Шардинг таблицы `users` по Shard Key (User_ID):**
  * **Шард 1 (Сервер А1):** Пользователи с ID от 1 до 5 000 000 (или по правилу `ID % 2 == 0`).
  * **Шард 2 (Сервер А2):** Пользователи с ID от 5 000 001 и далее (или по правилу `ID % 2 != 0`).
* **Шардинг таблицы `books` по Shard Key (Категория/Жанр):**
  * **Шард 1 (Сервер Б1):** Книги жанров "Художественная литература", "Детективы", "Фантастика".
  * **Шард 2 (Сервер Б2):** Книги жанров "Наука", "Учебная литература", "IT и Технологии".

##### 3. Режимы работы серверов
* **Прокси / Балансировщик (Router Layer):** Прослойка (например, ProxySQL или встроенная логика приложения), которая анализирует Shard Key в запросе и направляет его на строго определенный сервер.
* **Master-серверы (на каждом шарде):** Работают в режиме **Read/Write** (прием и чтение, и запись данных).
* **Slave-серверы (реплики):** Работают в режиме **Read-Only** (только чтение). Используются для резервного копирования и разгрузки master-серверов от тяжелых SELECT-запросов.
