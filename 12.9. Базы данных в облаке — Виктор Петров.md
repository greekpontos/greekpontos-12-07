\### Цель выполнения задания:

1\. Создать отказоустойчивый облачный кластер Managed Service for PostgreSQL в Yandex Cloud.

2\. Проверить работу репликации между зонами доступности с помощью утилиты `psql`.



\---



\### Ход выполнения задания



\#### Этап 1. Создание кластера PostgreSQL в Yandex Cloud

1\. Перешел в консоль Yandex Cloud в сервис \*\*Managed Service for PostgreSQL\*\*.

2\. Создал кластер со следующими характеристиками:

&#x20;  \* \*\*Класс хоста:\*\* `s2.micro`.

&#x20;  \* \*\*Тип диска:\*\* `network-ssd`.

&#x20;  \* \*\*Хосты:\*\* 2 хоста, размещенные в разных зонах доступности (например, `ru-central1-a` и `ru-central1-b`).

&#x20;  \* \*\*Сеть:\*\* Для обоих хостов включена опция \*\*«Публичный доступ»\*\* (назначены публичные IP-адреса).

&#x20;  \* \*\*БД и пользователь:\*\* Задал имя базы данных, имя пользователя и пароль.

3\. Дождался изменения статуса кластера на \*\*`RUNNING`\*\*.

\#### Этап 2. Подключение к master-узлу и проверка его статуса

1\. Скачал официальный SSL-сертификат Yandex Cloud для безопасного подключения.

2\. Подключился к кластеру через терминал с помощью утилиты `psql`, используя строку подключения с параметром `target\_session\_attrs=read-write` для автоматического выбора мастера:

&#x20;  ```bash

&#x20;  psql "host=c-xxxxxx.rw.mdb.yandexcloud.net port=6432 dbname=my\_db user=my\_user sslmode=verify-full sslrootcert=\~/.postgresql/root.crt target\_session\_attrs=read-write"

&#x20;  ```

3\. Проверил роль текущего узла с помощью SQL-запроса:

&#x20;  ```sql

&#x20;  select case when pg\_is\_in\_recovery() then 'REPLICA' else 'MASTER' end;

&#x20;  ```

&#x20;  \* \*\*Результат вывода:\*\* `MASTER`

4\. Проверил количество подключенных реплик к данному мастеру:

&#x20;  ```sql

&#x20;  select count(\*) from pg\_stat\_replication;

&#x20;  ```

&#x20;  \* \*\*Результат вывода:\*\* `1`



\---



\#### Этап 3. Проверка работоспособности репликации в кластере

1\. Находясь на \*\*MASTER\*\*-узле, создал тестовую таблицу и добавил в нее запись для проверки синхронизации:

&#x20;  ```sql

&#x20;  CREATE TABLE test\_table(text varchar);

&#x20;  insert into test\_table values('Строка 1');

&#x20;  ```

2\. Вышел из сессии мастера командой `\\q`.

3\. Подключился заново, но уже целенаправленно к узлу-реплике. Для этого убрал параметр `target\_session\_attrs` и указал хост конкретной реплики.

4\. Проверил роль узла, чтобы убедиться, что я на реплике:

&#x20;  ```sql

&#x20;  select case when pg\_is\_in\_recovery() then 'REPLICA' else 'MASTER' end;

&#x20;  ```

&#x20;  \* \*\*Результат вывода:\*\* `REPLICA`

5\. Проверил состояние процесса приема логов предзаписи (WAL):

&#x20;  ```sql

&#x20;  select status from pg\_stat\_wal\_receiver;

&#x20;  ```

&#x20;  \* \*\*Результат вывода:\*\* `streaming`

6\. Выполнил финальный проверочный запрос на чтение из созданной таблицы, чтобы подтвердить успешную репликацию данных между зонами доступности облака:

&#x20;  ```sql

&#x20;  select \* from test\_table;

&#x20;  ```
